# 汎用リスト管理

## 目的

PETITでNotionタスクだけでなく、アニメ・映画・買い物・読みたい本などの一覧を会話から管理する。

## 会話フロー

リスト操作は、正規表現で言い方を固定せず、文脈駆動Agent Runtimeが`lists_and_tasks` Capability内のToolを選ぶ。

例:

```text
ユーザー: 新しくリスト作りたい
PETIT: get_listsで現在のリストを確認
PETIT: 今は、タスク（Notion）、アニメリスト（ローカル）があるよ。ほかに作る？
ユーザー: 映画リスト
PETIT: create_listの確認を表示
```

項目追加も同じAgentループで処理する。

```text
ユーザー: 科学大キャンプリストに、iPhoneコースガイド見るって追加
PETIT: get_listsで対象を確認
PETIT: add_list_itemの確認を表示
承認後: 書き込み結果をAgentへ戻し、自然な最終回答を生成
```

次のような表現差はLLMが文脈から判断する。

- `科学大キャンプリストに、iPhoneコースガイド見るって追加`
- `アニメリストにフリーレンを追加して`
- `葬送のフリーレンをアニメリストに追加して`
- `買い物一覧に牛乳入れて`

`科学大キャンプについて`のような話題提示だけでは、リスト作成や項目追加を推測しない。

## Tool

- `get_lists`: 組み込みタスクとカスタムリストを保存先つきで返す
- `create_list`: カスタムリストを作る。確認必須
- `get_list_items`: タスクまたはカスタムリストの中身を返す
- `add_list_item`: カスタムリストへ項目を追加する。確認必須

Agentには同じCapability内でタスクToolも渡されるため、会話文脈・対象リストの存在・Tool結果から、リストとタスクを区別する。

## 保存先

- タスク: Notion設定済みなら`Notion`、未設定なら`ローカル`
- カスタムリスト: 現時点ではローカルSQLite

テーブルは`list_collections`と`list_items`を必要時に作成する。リスト側に`source`を保持するため、将来はリスト単位でNotionデータベースを接続できる。

## 安全境界

- `タスク`は組み込みリストとして重複作成しない
- 同名のカスタムリストを重複作成しない
- 作成と項目追加は確認待ちフローを通す
- 対象が曖昧な場合は勝手に別概念へ変換しない
- カスタムリスト追加要求を、名前の似たプロジェクトへのタスク作成に変換しない
- Notion上の新規データベースは自動作成しない

## 旧パーサー

`list_conversation.py`は回帰比較のため当面残すが、通常の会話入口からは使用しない。正本は`docs/contextual_agent_runtime.md`に記載した文脈駆動Agent Runtimeとする。
