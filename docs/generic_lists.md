# 汎用リスト管理

## 目的

PETITでNotionタスクだけでなく、アニメ・映画・買い物・読みたい本などの一覧を会話から管理する。

## リスト作成フロー

1. ユーザー: `新しくリスト作りたい`
2. PETIT: `今は、タスク（Notion）、アニメリスト（ローカル）があるよ。ほかに作る？`
3. ユーザー: `映画リスト`
4. PETIT: `新しく「映画リスト」を作る？`
5. 承認後、`create_list`を実行する

明示的に`アニメリスト作って`と言われた場合も、現在のリストを確認してから同じ作成確認へ進む。

作成確認後の短い返答でも、`〜について`、`〜を教えて`、`〜を見せて`などの話題・参照要求は新しいリスト名として扱わない。

## 項目追加フロー

既存のカスタムリスト名が明示された場合は、汎用Agentへ渡す前に決定論的に`add_list_item`へ接続する。

対応例:

- `科学大キャンプリストに、iPhoneコースガイド見るって追加`
- `アニメリストにフリーレンを追加して`
- `葬送のフリーレンをアニメリストに追加して`
- `買い物一覧に牛乳入れて`

対象リストが存在する場合は、追加前の確認を返す。存在しない場合は、タスク作成へフォールバックせず、リストが見つからないことを案内する。

組み込みのタスクリストが明示された場合だけ、同じ自然言語パターンから`create_task`へ接続する。

## Tool

- `get_lists`: 組み込みタスクとカスタムリストを保存先つきで返す
- `create_list`: カスタムリストを作る。確認必須
- `get_list_items`: タスクまたはカスタムリストの中身を返す
- `add_list_item`: カスタムリストへ項目を追加する。確認必須

## 保存先

- タスク: Notion設定済みなら`Notion`、未設定なら`ローカル`
- カスタムリスト: 現時点ではローカルSQLite

テーブルは`list_collections`と`list_items`を必要時に作成する。リスト側に`source`を保持するため、将来はリスト単位でNotionデータベースを接続できる。

## 安全境界

- `タスク`は組み込みリストとして重複作成しない
- 同名のカスタムリストを重複作成しない
- 作成と項目追加は既存の確認待ちフローを通す
- カスタムリスト追加要求を、名前の似たプロジェクトへのタスク作成に変換しない
- Notion上の新規データベースは自動作成しない
