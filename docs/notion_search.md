# Notion会話検索

PETITから、Notionに共有されたページを読み取り専用で検索する機能です。

## 目的

次のような明示的な依頼で、Notionを実際に検索して本文に基づいて回答します。

```text
Notionから卒研に関する情報あったら、今どんな感じか教えて
NotionでPETITの設計メモを探して
```

通常の雑談ではNotion APIを呼びません。

## 処理フロー

1. Python側で `Notion` と読み取り意図を検出する
2. 発話から短い検索語を決定論的に抽出する
3. Notion Search APIを1回だけ呼ぶ
4. 上位最大3ページから、プロパティと本文を上限付きで取得する
5. 結果が見つかった場合だけ、Agentモデルを1回呼んで回答を整理する
6. 未設定・0件・API失敗は、LLMを呼ばずに状態をそのまま返す

検索時の既定上限は次のとおりです。

- 検索結果: 3件（最大5件）
- ページ本文: 1ページあたり1200文字（最大2400文字）
- 子ブロック探索: 深さ2

PDFのダウンロード、RAG同期、全ページ走査は行いません。

## ツール結果

`search_notion` は次の状態を区別します。

| status | 意味 |
|---|---|
| `found` | 該当ページを取得した |
| `not_found` | 検索は成功したが0件だった |
| `not_configured` | `NOTION_API_KEY` が未設定 |
| `invalid_query` | 検索語を抽出できなかった |
| `error` | Notion APIや通信に失敗した |

取得結果には、ページタイトル、URL、最終更新日時、主要プロパティ、本文抜粋を含めます。個別ページの本文取得だけ失敗した場合は、そのページの `content_error` に保持し、他の候補は返します。

## 安全境界

- 読み取り専用で、Notionを書き換えない
- インテグレーションへ共有されていないページは取得できない
- 明示的なNotion読み取り依頼だけで実行する
- `Notionを同期して` は既存の `sync_notion_tasks` を使い、検索とは分離する
- 検索結果がない状態を、取得不能や検索未実行と混同しない

## 制約

Notion Search APIはページやデータソースの名前検索を主目的としており、ワークスペース全体の完全な本文全文検索ではありません。そのためPETITは、検索で得た上位候補の本文とプロパティを追加取得して回答精度を補います。

## テスト

```bash
python -m unittest tests.test_notion_search -v
python -m compileall backend tests/test_notion_search.py
```

実環境では次を確認します。

1. Notionインテグレーションに対象ページを共有する
2. `NOTION_API_KEY` を設定してPETITを再起動する
3. 「Notionから卒研に関する情報あったら、今どんな感じか教えて」と送る
4. 詳細欄で `search_notion` が1回実行されていることを確認する
5. 返答の内容と参照URLがNotionページに一致することを確認する
