# PETIT Renaissance — Vision & Experience

> **PETIT Renaissance**  
> 自分だけのAI秘書を、生活・記憶・ファイル・制作・開発を横断して仕事を進める「日常のインターフェース」へ進化させる。
>
> Status: **Vision / Aspirational**  
> Last updated: **2026-10-22**  
> Scope: **理想像と期待する体験のみ**。実装方式、工程、優先順位、Issue分解、完了条件は本書では定義しない。

## 1. ビジョン

PETITは、単なるチャットボットでも、情報検索ツールでもない。

**「話しかけるだけで、必要な情報を見つけ、状況を理解し、複数の道具やAIに仕事を任せ、結果を届けてくれる、自分専用のAI秘書」**を目指す。

外出先のiPhone、作業机のDesktop、Discordのどこからでも自然に呼び出せる。途中で端末や会話の場所が変わっても、PETITはユーザーのプロジェクト、決定、タスク、作業結果を必要に応じて取り出せる。

目指すのは、機能の多さではなく、**「頼む → 任せる → 状況を知る → 確認する → 続ける」**が途切れない体験。

この構想は既存の `Concept.md` にある `PETIT_AS_JARVIS` の延長にある。PETITの人格、生活支援、記憶、音声、既存のデスクトップ体験を捨てる刷新ではない。

## 2. 体験の原則

1. **入口は複数、秘書はひとり。** Web/PWA・Desktop・Discordがそれぞれ別のAIや別の仕事台帳にならない。
2. **会話は独立、過去の知識は横断検索。** 別セッションの発言を現在の会話へ無条件に混ぜない。一方、必要なときには過去の会話を検索できる。
3. **自然言語が操作の入口。** ユーザーは機能名やコマンドを覚える必要がない。PETITが目的を理解し、必要な能力を選ぶ。
4. **AIに判断を任せ、結果は確かめる。** PETITは実際に観測・取得・実行できたことと、AIの推測や未確認事項を区別する。
5. **一度頼んだ仕事を見失わない。** 会話を閉じたり端末を変えたりしても、依頼、進捗、承認待ち、成果物、次の行動に戻れる。
6. **ユーザーのプライバシーと主導権を守る。** 個人ファイルや会話を勝手に公開せず、外部送信や影響の大きい操作は意図と送信先を確認する。
7. **既存のPETITを育てる。** 生活・予定・記憶・Notion・BRAIN・制作支援など、これまでの価値を保持したまま能力を拡張する。

## 3. どこからでも同じPETITを使う

### iPhone / Web・PWA

スマートフォンから、通常の会話だけでなく、次のことができる。

- 会話をスレッドごとに開き、過去の相談へ戻る。
- タスクを一覧し、相談しながら整理・追加・確認する。
- プロジェクトごとの現在地、開発依頼の稼働状況、作業結果、承認待ちを見る。
- PCやGoogle Driveにある必要なファイルを探して受け取る。
- 完了通知を受け取り、その場で続きを指示できる。

### Desktop

PETITの主たる作業環境。小型会話、作業画面、音声、状況把握、通知などの既存体験とつながる。

PCの前にいるときは、直前までの作業や対象プロジェクトを理解した相談相手として機能する。デスクトップで開始した仕事も、スマホから参照できる。

### Discord Bot

**自分専用のBot**として動作する。本人のDiscordアカウント以外には個人秘書の操作権限を与えない。

- DMや許可した場所で、メンションまたはコマンドからPETITへ指示できる。
- 会話、タスク確認、開発指示、進捗確認、ファイル検索・添付ができる。
- 必要なときだけ開発完了、失敗、確認待ちなどを通知する。
- Discord固有の会話は独立して保存され、ほかの会話と自動で合流しない。
- ただしPETITは、許可された過去のDiscord会話を後から検索して参照できる。

## 4. 会話と記憶：独立したスレッド、つながる知識

PETITの会話は、端末や場所にかかわらず**スレッド（セッション）ごとに独立**する。

- Webの会話A、Discordの会話B、Desktopの会話Cは、それぞれ独立した入力・出力・履歴を持つ。
- どこかの発言を別のスレッドへ自動コピーしない。
- AIは、質問への回答に必要な場合だけ、**別セッションの過去の発言を検索できる**。
- 検索結果には、元のスレッド、発言日時、関連プロジェクトなど出典を添え、過去の決定・現在の観測・推測を区別する。
- 過去会話の検索と、BRAIN等への長期知識の保存は別の概念として扱う。
- 会話の独立性は、必ずしも物理的なデータベースの分離を意味しない。

**目指す体験**

> 昨日DiscordでWEVORAの仕様を相談した。翌日Webで「昨日決めた内容を踏まえて続きを考えて」と言えば、PETITが該当会話を探し、決定事項を確認したうえで応答する。

## 5. 生活と制作を横断する秘書

PETITは、既存の会話・記憶・予定・タスク・リマインダー・Notion・Obsidian BRAIN・プロジェクト情報を、必要な場面で組み合わせて扱えることを目指す。

- 「今日何をしたらいい？」に、予定・期限・中断した作業を踏まえて答える。
- 「この話、前にした？」から過去の会話やメモを探す。
- 「これをタスクにして」「先週の決定をまとめて」に自然な言葉で対応する。
- 「次に何をやるべき？」に、ただ一覧を返すだけでなく、今取り組みやすい次の一手を提案する。
- 作業を始める・中断する・振り返る・再開する、という生活と制作の流れがつながる。

## 6. ファイルを探し、理解し、届ける

「PCのどこかにあるファイル」を、保存場所や正確なファイル名を思い出せなくても探せる。

対象にしたい情報源は、**Windowsのローカルファイル、Everythingで見つかるファイル、エクスプローラーに表示されるGoogle Drive、必要に応じたクラウド上のGoogle Driveファイル**。

理想は次のような体験。

> 「前に作った履歴書の最新版をここに送って」  
> PETITが候補を探し、必要なら内容や更新情報を見て候補を絞り、本人の確認を得て、今いるWebチャットやDiscordへ添付する。

目指す能力は以下。

- ファイル名、場所、種類、更新時期、文書内容を手掛かりに探す。
- 候補が複数ある場合は、わかった根拠を示して確認する。
- ファイルを読む・要約する・会話で扱う・添付として届ける。
- PC上のファイルとGoogle Drive上のファイルを、ユーザーにとって一貫した検索体験にする。
- クラウド上に実体がないファイルやGoogle Docs等の特殊な形式は、取得可否や制約を正しく伝える。

**検索できることと、外部へ送信してよいことは別。** 履歴書などの個人情報、送信先、閲覧権限には特に注意する。秘密情報や私的な領域を無制限に収集することは目指さない。

## 7. 開発を任せるAI秘書

PETITを、複数の開発プロジェクトの**司令塔**としても使いたい。

ユーザーはiPhoneでもDiscordでもDesktopでも、普段の言葉で「WEVORAの続きを進めて」「この不具合を調べて」「いま開発はどうなっている？」と頼める。

PETITは、対象プロジェクト、前回の決定、リポジトリの状況、進行中のタスクを踏まえて、必要な開発エージェントに仕事を委譲し、結果を追跡する。

### AIの役割イメージ

- **Antigravity CLIを第一候補の会話・判断・ルーティングの頭脳**として使いたい。軽い会話や仕事の整理にも活かし、利用枠を有効活用したい。
- **Codex CLIを主な開発Worker**として使いたい。調査、実装、修正、テスト、レビューなどの実作業を担当する。
- 必要に応じて複数の作業エージェントへ仕事を振り分け、結果をPETITが取りまとめる。
- モデルやCLIの利用状況・残り枠・実行中の仕事を把握し、無駄な使用量を減らしたい。
- 特定モデルの利用が難しい場合でも、PETITの人格・記憶・タスク・会話が失われないことを望む。

**注意:** Antigravity CLIの自作アプリへの組み込み可否、プラン上の許可範囲、利用量・残量の取得可能範囲は、実用化に向けて確認を要する。本書は希望する体験を述べるもので、利用許諾や実装済みを主張しない。

### 開発状況が「見える」

PETITの開発タブや会話から、以下を把握できる。

- どのプロジェクトで、何を依頼しているか。
- 誰が・どのAIが担当しているか、実行中か停止中か。
- 実施した作業、Gitの変更、PR、テスト・CI、失敗・未確認事項。
- 次に必要な承認や人間による確認。
- 作業がどこまで進んでいて、何をもって完了とするか。

AIが「完了した」と言っただけでは完了扱いにせず、実行・変更・テスト・人間の確認を区別する。

## 8. 共通の仕事と画面

PETITで扱う仕事には、会話、タスク、開発ジョブ、通知、ファイル送信などがある。これらは別々のアプリに閉じず、同じPETITの現在地として参照できる。

Web/PWAで期待する主な画面像：

| 領域 | 期待する体験 |
| --- | --- |
| Chat | スレッド型の独立した会話。必要に応じて横断検索 |
| Tasks | 予定・個人タスク・プロジェクトタスクの確認と整理 |
| Development | 開発依頼、進捗、結果、Git/PR、承認待ちを一望 |
| Files | ローカル・Driveのファイルを探し、受け取り、会話で扱う |
| Notifications | 完了、失敗、確認待ち、重要な変化を確認 |

見た目のタブ構成や名称は将来のUIデザインで検討する。ここでは、**いつでも状態へ戻れること**を期待体験とする。

## 9. PETITの「能力」の考え方

ユーザーは「どのツールを呼ぶか」ではなく、**「何をしたいか」**を伝える。

PETITのAIが意図に応じて、ファイル検索、会話検索、開発状況取得、タスク操作、Discord通知などの能力を選び、必要な順番で使うことを目指す。

能力の名前や呼び出し方式を覚える必要はない。新しい能力をPETITに追加すると、複雑な言い回しを個別に教え込まなくても、自然な依頼に応えられる秘書へ成長してほしい。

その一方、AIの自由な判断だけで送信済み・実装完了・保存成功と断定しない。**実際の結果と、できなかった理由がわかること**を重視する。

## 10. こんな一日を実現したい

**朝・Desktop**  
「おはよう。今日どうしよう？」に予定とタスク、昨夜の開発結果を踏まえて答える。

**移動中・iPhone**  
「WEVORAの敵AIの改善をお願い」と頼む。PETITが開発依頼として引き受け、作業状態が画面に残る。

**作業中・Discord**  
「@PETIT 進捗どう？」と聞く。PETITが同じ開発ジョブの状況を確かめて答える。

**ファイルが必要になったとき**  
「履歴書をここへ送って」と言う。PETITがPCやDriveから探し、適切な宛先へ添付する。

**夜・Web**  
「今日何が進んだ？」と聞けば、タスク・開発結果・未確認事項をまとめ、明日の再開地点を残せる。

## 11. 目指さないこと・守りたいこと

- 複数の画面やBotごとに別の人格・別の記憶を作って分裂させない。
- 全セッションの会話を無条件に連結しない。
- すべてのファイルを常時AIへ読み込ませたり、外部へ送ったりしない。
- 技術的な操作ができることと、その操作をユーザーが許可したことを混同しない。
- 進捗・ファイルの存在・モデル使用量・操作成功を推測だけで表示しない。
- 既存のPETITが持つ生活支援・制作支援の方向性を、開発専用ツールへ置き換えない。
- 最初から他人向けの汎用Discord Botやマルチユーザーサービスを目指さない。

| タスク | 共通のタスクを確認・整理できる専用画面がほしい |

| Brain候補 | Antigravity CLIを会話・判断・ルーティングに活用したい |
| 開発Worker候補 | Codex CLIを主力としたい |

## 13. 今後の対話で深めたい理想上の問い

これらは**未決定の体験要件**であり、実装タスクではない。

- 開発依頼をPETITがどの程度まで自律的に進め、どの操作で必ず本人確認を求めるか。
- Discordへの通知をどのくらい積極的に行うと快適か。
- 会話・タスク・開発ジョブ・ファイルが、画面上でどの程度結び付いて見えるべきか。
- PCがスリープ・オフラインのとき、どの機能を使える状態にしたいか。
- 過去会話やファイルを検索したとき、出典とプライバシーをどう見せるのが自然か。
- AIの使用量と品質、処理速度のバランスをどのようにユーザーへ見せたいか。
