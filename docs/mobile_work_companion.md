# スマホ向け制作伴走モード

## 目的

PETITを受け身のチャットではなく、制作中の状態を見守り、必要なときだけ短く声をかける相棒として使う。

## 画面

ホーム上部に次を常時表示する。

- 今やっていること
- 作業経過時間
- 声かけ頻度
- 今日の次の一手
- 次の予定
- Highタスク最大3件

通常の会話表示は直近3ラリーに絞り、`履歴を見る`で同一セッション内の復元済み履歴を展開する。

## 作業モード

作業内容を入力して`作業開始`を押す。状態はブラウザの`localStorage`とサーバー側SQLiteへ保存するため、再読み込み後も復元され、画面を閉じていても継続確認と停止期限を判定できる。

操作:

- `一時停止`: 経過時間と定期声かけを止める
- `再開`: 停止時間を除いて計測を再開する
- `今声かけて`: 次回時刻を待たず、現在状態から短い声かけを生成する
- `終了`: 経過時間と状態をPETITへ渡して振り返りを生成する
- `まだ続けてる`: 20分ごとの継続確認へ返答し、次の確認を20分後へ延ばす

声かけ頻度:

- 10分ごと
- 20分ごと
- 区切りだけ
- 静かにする

## 自律的な声かけ

Web版では、次をすべて満たすときだけ定期チェックを実行する。

- 作業モードがON
- 一時停止中ではない
- PETIT画面が表示中
- 前回チェックから設定間隔が経過

内部イベントとして次の状態を既存`/api/chat`へ渡す。

- 現在の作業
- 経過時間
- 画面の表示状態
- 最後の画面操作からの秒数
- 次の予定
- Highタスク
- 前回の声かけ

内部イベントには`[PETIT_INTERNAL_EVENT]`を付ける。SQLiteには継続用に保存されるが、履歴復元時はユーザー発話として表示しない。

## バックグラウンドの継続確認

前景の短い声かけ頻度とは別に、サーバーは進行中の作業を20分ごとに確認する。

1. 作業開始から20分後に「まだ続けてる？」を通知する
2. `まだ続けてる`ボタンまたは通常のチャット返信を受け取ると、次の確認を20分後へ延ばす
3. 確認から20分返事がなければ、作業を`auto_stopped`にして時間の加算を止める
4. 自動停止も通知履歴へ残し、Push設定済み端末へ配信する

通知拒否、購読なし、VAPID未設定でもSQLite上の停止判定は行う。以前のブラウザ状態だけが40分以上残っており、対応するサーバー状態がない場合も、再表示時にローカル計測を停止する。

## セッション分離

最後の利用から2時間以上空いて起動した場合、新しい`session_id`を作る。

表示名は次の形式。

```text
2026-07-25・1回目
2026-07-25・2回目
```

内部IDには日付、当日回数、UUIDを含める。

## 途中経過メッセージ

調査・確認・追加などの依頼は、結果前に短い状態メッセージを表示する。

```text
ちょっと調べてみるね！
見つけた！〜
```

状態メッセージは一時表示で、会話履歴へは保存しない。音声応答ON時は既存のMutationObserverにより読み上げ対象になる。

## PWA

主なファイル:

- `frontend/manifest.webmanifest`
- `frontend/service-worker.js`
- `frontend/icon.svg`

ルートService Workerは静的シェルのネットワーク優先キャッシュとWeb Push受信をまとめて扱う。`/api/`はキャッシュしない。旧`frontend/sw.js`は既存インストール互換のため残しているが、新しいPWA起動先と通知購読はルートスコープを使う。

Web Pushの設定、通知カテゴリ、API、実iPhone確認は[`web_push_notifications.md`](web_push_notifications.md)を参照する。

## 制限

iPhoneでWebアプリがバックグラウンドへ移ると、JavaScriptタイマーの正確な継続実行は保証されない。画面内の短い声かけは前景動作に限定し、20分ごとの継続確認と自動停止はPETITサーバーが判定する。PETITサーバー自体が停止している間は通知と期限判定を実行できない。SwiftUIネイティブ版とAPNs Providerは別工程で扱う。
