# 文脈駆動Agent Runtime

## 目的

PETITは、ユーザー発話を正規表現で個別Toolへ固定せず、直近の会話と元の依頼からLLMが目的・必要な機能領域・Tool・終了を判断する。

コード側は、LLMの判断を無制限に実行せず、回数・権限・承認・重複・結果圧縮を管理する。

## 全体フロー

```text
ユーザー発話
  ↓
Project Continuity / 即時応答の安全ゲート
  ↓
Capability Router（Chatモデル）
  ↓
選択されたCapability内のToolだけをAgentへ公開
  ↓
AgentモデルがToolまたは最終回答を選択
  ↓
読み取りTool実行 → 圧縮結果をAgentへ戻す
  ↓
不足なら次のTool、十分なら最終回答
  ↓
書き込みToolなら確認待ち
  ↓
承認後に書き込み実行 → 保存状態からAgentを再開 → 自然な最終回答
```

## Capability

| Capability | 主な対象 |
|---|---|
| `lists_and_tasks` | タスク、Notionタスク、任意リスト、リスト項目 |
| `calendar` | 時刻、天気、予定、カレンダー |
| `knowledge` | BRAIN、Notion、記憶の検索と編集 |
| `github` | GitHubの開発状況、差分、候補紐付け |
| `web` | ニュース、外部調査 |
| `memory` | 長期記憶、要約、復帰、引き継ぎ |
| `projects` | PETIT内部プロジェクトの保存済み状況、現在のcheckpoint、外部ソース候補 |

Routerは正確なTool名や引数を生成しない。機能領域だけを最大4件選び、Agentが登録済みToolから正確な処理を選ぶ。

## Agentループ

- Toolラウンド上限: `PETIT_MAX_TOOL_ITERATIONS`。既定3、最大6
- Tool総呼び出し上限: 6
- 同一Tool・同一引数: 1回まで
- 元の依頼: 最終回答まで保持
- Tool結果: 文字列・配列・辞書を上限付きで圧縮
- 登録されていないTool: 実行しない
- 許可Capability外のTool: 実行しない
- 読み取り依頼への「確認します」「調べます」だけの最終回答: 1回だけ同一ターン内のTool実行を再要求
- 再要求後も作業予告だけの場合: 未実行を明示して失敗扱いにし、会話履歴へ成功結果として保存しない

Tool結果を受け取るたび、Agentは次を判断する。

1. 元の依頼を満たしたか
2. 追加Toolが本当に必要か
3. 対象が曖昧で確認が必要か
4. 書き込み確認へ進むか

## 文脈削減

全文を毎ラウンド要約する追加LLMは使わない。

- 直近履歴は件数・文字数で制限
- `original_request`は削除しない
- Tool結果から埋め込み、raw、debugなどのノイズを除外
- 長い文字列、配列、深いネストを上限付きで切る
- Agentへは元の依頼と圧縮結果だけを戻す

これにより、LLMへ「不要部分を無視して」と頼むだけでなく、入力自体を小さく保つ。

## 進捗イベント

Tool実行中の表示は通常の会話メッセージではなく、`agent_progress` jobとして配信する。

主なイベント:

- `planning`: 要望と必要情報を整理
- `tool_started`: Tool実行開始
- `tool_finished`: Tool実行終了
- `finalizing`: 最終回答を整理

フロントエンドは入力中バブルの文言だけを更新する。進捗は次へ保存しない。

- 会話履歴
- Markdownログ
- RAG
- 長期記憶

最終回答後に遅れて届いたイベントは表示せず、配信済みにする。

## 書き込み承認と再開

Agentが確認必須Toolを選んだ場合、そのToolを実行せず、次をSQLiteへ短期保存する。

- 元の依頼
- 圧縮済みメッセージ
- Capability
- 使用済みTool
- 重複検出情報
- Toolラウンド数
- request / session ID

確認UIには、内部Tool `execute_agent_write` を登録する。

承認後:

1. 対象の書き込みToolを実行
2. Tool結果を圧縮
3. 保存したAgent状態へ戻す
4. 読み取りToolだけを許可して必要なら確認
5. 自然な最終回答を生成
6. 再開状態を削除

再開状態のTTLは30分。

## 安全境界

- 書き込みToolは確認なしに実行しない
- 確認対象でないToolを内部ラッパーから実行しない
- 同じToolの同じ引数を繰り返さない
- Tool上限に達したら停止して対象を絞るよう案内する
- Tool結果にない外部事実を最終回答へ追加しない
- 話題提示を作成・変更操作へ勝手に変換しない
- Toolが必要な依頼を、実行していない作業予告だけで完了扱いしない

## 移行方針

`list_conversation.py`や`task_conversation.py`の既存パーサーは、回帰比較のため当面残す。ただし通常の`agent.run()`入口からは呼び出さず、文脈駆動Agent Runtimeを正本とする。

安定後に、不要な決定論パーサーと互換テストを段階的に削除する。
