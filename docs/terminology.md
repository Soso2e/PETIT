# PETIT用語集

PETIT内で使う概念の意味を固定し、会話・UI・実装で言葉がぶれないようにするための用語集です。

## タスク

実行して完了する具体的な作業です。

- 期限、優先度、状態を持てる
- 必要に応じてプロジェクトに紐付く
- 主な保存先はNotionタスクDBとPETITのSQLiteミラー

例:

- 引き継ぎを書く
- Google OAuthを公開設定にする
- Mayaツールを再読み込みできるようにする

## プロジェクト

複数のタスク、進捗、会話、外部情報をまとめる継続的な取り組みです。

- 終了条件や目的を持つ
- タスクをまとめる単位になる
- GitHub、Notion、BRAIN、Linkraftなどの外部ソースを紐付けられる
- 現在地、次の一手、ブロッカーを保持する

例:

- PETIT開発
- Linkraft開発
- 卒業研究

## リスト

後から見返したい項目や候補を並べておく一覧です。実行期限や完了管理を主目的にしません。

- アニメ、映画、買い物、読みたい本などに使う
- 現在はPETITのローカルSQLiteへ保存する
- ユーザー向け名称は「リスト」を使う
- `list_collections`などの「collection」は内部実装名として扱う

例:

- 見たいアニメリスト
- 読みたい本リスト
- 買いたいものリスト

## 記憶

PETITが後から思い出すべき、ユーザーの好み、前提、決定事項などです。

- 項目を並べるための一覧ではない
- 会話をまたいで参照したい事実に使う
- 長期記憶やBRAINへ保存する

例:

- Netlifyを使うプロジェクトではdevelopへPRを出す
- QwenはThinking OFFで使う
- ユーザーはMayaとUnityを使う

## 引き継ぎ

作業を中断し、後から再開するための現在地です。

- どこまで終わったか
- 次に何をするか
- 未確認事項やブロッカー

引き継ぎ自体はタスクやプロジェクトとは別の概念です。ただし「引き継ぎを書く」は実行する作業なのでタスクになります。

## 判断ルール

| 発話・情報 | 扱い |
|---|---|
| 今日までに引き継ぎを書く | タスク |
| PETIT開発を進める | プロジェクト |
| 見たいアニメを追加する | リスト |
| この設定を覚えておいて | 記憶 |
| 今日はここまで。次はOAuth確認 | 引き継ぎ |

迷った場合は次の基準で判断します。

1. 実行して終わるものはタスク
2. 複数の作業をまとめる継続単位はプロジェクト
3. 後から選ぶ、見る、参照する項目群はリスト
4. PETITが会話をまたいで思い出す事実は記憶
5. 中断地点と次の一手は引き継ぎ
